01 · 先搞懂

HTML 到底是什么？

<h1>

HTML 的全称是 HyperText Markup Language，中文叫“超文本标记语言”。

它不是用来做计算和判断的编程语言，而是用一组标签告诉浏览器：这段是标题、那段是正文、这里放图片、那里可以跳转。

HTML VERSION LOG

从简单文档，到现代应用平台

HTML 并不是一次设计完成的。它随着网页需求不断生长；今天学习的是持续更新的 HTML Living Standard。

  1. 1993
    HTML 1.0

    最早版本，只能组织基本文字与链接。

  2. 1995
    HTML 2.0

    形成统一标准，表单、表格等能力逐渐成熟。

  3. 1999
    HTML 4.01

    与 CSS、脚本协作，网页开始承担复杂界面。

  4. 2000
    XHTML 1.0

    借用 XML 规则，强调严格闭合与规范语法。

  5. 2014 → NOW
    HTML5 / Living Standard

    加入视频、音频、绘图、语义标签与丰富原生交互，并持续更新。

    当前主流
别等“HTML6”

现在的 HTML 采用“活标准”模式，小功能会持续进入规范和浏览器，而不再等待一个大版本统一发布。

SEMANTIC DECISION TABLE

看起来相似，表达的意思不同

浏览器默认样式可以被 CSS 改写，标签携带的语义仍然保留。

<strong>重要、严重或紧急

表示内容的重要性，而不只是加粗。适合安全警告、必须完成的要求。

例：账号将在今天失效
<em>着重强调语气

改变一句话的重音，强调位置不同可能改变句意，可以嵌套增强强调程度。

例：你必须保存文件
<b>吸引注意，但不增加重要性

适合摘要中的关键词、文章引导词等。若内容确实重要，应选择 strong。

例：关键词：HTML 语义
<i>不同语态或习惯性斜体内容

适合术语、外语短语、思想活动、物种名等；着重语气应使用 em。

例：术语 viewport
<u>非文字性质的标注

适合标记拼写错误或中文专名等注记。不要只为下划线使用，也要避免与链接混淆。

例：HTLM 拼写错误
<del>内容已从文档中删除

用于价格、时间或文档修订；可用 datetime 记录删除时间。

例：原价 ¥299　现价 ¥199
<mark>与当前上下文相关

突出搜索结果、引用中需要关注的片段。它表示相关性，不等于重要性。

例：找到 3 个 HTML 结果
快速选择重要 / 紧急 → strong语气重音 → em引起注意 → b术语 / 异声 → i注记 → u已删除 → del当前相关 → mark

关于下标和上标sub 与 sup 仍适用于 H2O、10m2、脚注编号等排版含义，不属于上述强调语义。

注释仍存在于源代码中，浏览器不把它绘制成页面内容。

注释适合解释结构和记录待办，但不能嵌套。用户可以查看网页源代码，因此不要在注释中保存密码、密钥或隐私信息。

3.9

带说明的媒体：figure

把图片、图表或代码示例与它的标题组织成一个完整单元。

<figure> <figcaption>
<figure>
  <img
    src="lab-diagram.svg"
    alt="HTML 源码经过浏览器解析形成页面结构"
    width="800"
    height="450"
  >
  <figcaption>
    图 1：浏览器把 HTML 解析为页面结构
  </figcaption>
</figure>

什么时候使用内容相对独立，可作为一个整体引用或移动，且移动后不影响正文主线时使用 figure；可选的 figcaption 必须是它的第一个或最后一个子元素。

alt 替代图片内容；figcaption 为整个 figure 提供可见说明，两者职责不同。

TABLE ANATOMY

每个标签只负责一种结构

<table>整个数据表

包住标题、表头和表体，是表格结构的根元素。

<caption>表格标题

说明这张表描述什么；通常是 table 内的第一个子元素。

<thead>表头行分组

组织列标题，打印长表格时浏览器可能重复显示表头。

<tbody>主体数据分组

组织主要数据行，一张表可以按需要包含多个 tbody。

<tr>一行单元格

每个 tr 内放置同一行的 th 或 td。

<th>标题单元格

用 scope 声明它负责一列还是一行。

<td>普通数据单元格

存放与行、列标题相对应的实际数据。

scope="col"列标题

表头“实践任务”负责解释它下方这一列中的所有数据。

↓　↓　↓
scope="row"行标题

第一列“第 2 周”负责解释它右侧这一行中的所有数据。

→　→　→
简单表格优先使用 scope

复杂的多级表头可能需要 id 与 headers 建立关联；初学阶段先把单层行列标题写正确。

手机适配不要为了窄屏删除重要列，也不要把 table 改成无语义的 div。可以给外层容器设置 overflow-x: auto，让用户横向浏览完整数据。

HarmonyOS · ArkTS声明式组件
@Entry
@Component
struct ProfileCard {
  build() {
    Column({ space: 12 }) {
      Image($r('app.media.avatar'))
        .width(96).height(96)
      Text('小明的学习卡').fontSize(24)
      Text('正在学习 HTML 与 ArkUI')
      List() {
        ListItem() { Text('页面结构') }
        ListItem() { Text('响应式布局') }
      }
      Button('关注学习').onClick(() => {
        // 更新状态或跳转页面
      })
    }.padding(24).width('100%')
  }
}
  1. 01
    先画结构树

    HTML 的父子嵌套对应 ArkUI 的组件嵌套，先识别 Column、Row、List 等容器。

  2. 02
    再迁移样式

    CSS 不会直接生效，要把尺寸、间距和颜色改写为 ArkUI 属性方法。

  3. 03
    最后重写交互

    链接、表单提交和 DOM 脚本需要改成 ArkTS 事件、状态管理与页面路由。

重要区别 ArkUI 没有浏览器 DOM，也不会解析你的 HTML/CSS。语义拆分和组件树思维可以迁移，代码本身需要用 ArkTS 重写。
