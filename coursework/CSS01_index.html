第 4 节建议 2 分钟

CSS 是什么

CSS，全称 Cascading Style Sheets（层叠样式表），是一种专门描述网页"长什么样"的样式语言。浏览器读取 HTML 得到结构，再读取 CSS 规则，把样式"刷"到对应元素上。

一个类比：HTML 是毛坯房和家具——墙、门、桌椅都在；CSS 是墙面刷漆、灯光布置和软装搭配。家具没换（内容没变），但住起来的感受完全不同。

为什么要把样式从 HTML 里分离出来

复用

一套样式表可以同时服务成百上千个页面，全站风格统一。

维护

改一处、全站生效。换一次主题色，不必逐页修改。

协作

结构与样式可以并行开发、分工负责，互不阻塞。

至于名字里的"层叠（Cascading）"——多条规则可以同时作用在同一个元素上，叠加生效、冲突时有约定的取舍规则。这个现象我们在第 7 节末尾做简要体验，本节课不展开。

第 5 节建议 3 分钟

CSS 基本语法

一条 CSS 规则由两部分组成：选择器与声明块。

选择器 {
属性名: 属性值;
}
选择器 · 改谁？p表示页面上所有的 p 标签（也可以是类、ID 等，下一节详讲）。
属性名 · 改什么？color、font-size……描述"哪方面的样式"。
属性值 · 改成什么样？blue、18px……样式的具体取值。
分号 · 一条声明结束最后一条声明的分号理论上可省，但建议每条都写——后面追加声明时不易出错。

最简单的完整示例

这段文字是普通的 <p> 段落，应用了上面的规则。

p { color: blue; font-size: 18px; }

选择器 p 命中所有段落；color 与 font-size 两条声明分别设置颜色和字号。

CSS 注释的写法

注释写给自己和未来的同事看："这段规则是干什么的、为什么这么写"。及时的注释是职业习惯，不是负担。

新手三大手误：① 声明结尾漏分号；② 用了中文标点（：；"" 必须是英文半角）；③ 漏写右大括号，导致后面的规则全部失效。
第 6 节建议 3 分钟

CSS 的三种引入方式

样式写在哪里？有三种方式，先看代码，再比较优劣。

方式一：行内样式（写在标签的 style 属性里）

方式二：内部样式（写在 head 的 style 标签里）

方式三：外部样式（单独的 .css 文件，用 link 引入）

三种方式对比

方式写法适用场景优点局限推荐程度
行内样式style="..."临时测试、极少量特殊样式直观、优先级最高结构与样式混在一起，无法复用，最难维护★★☆☆☆ 谨慎使用
内部样式<style>...</style>单页练习、课堂演示无需额外文件，便于演示样式不能被其他页面复用★★★☆☆ 练习可用
外部样式<link rel="stylesheet">真实项目（多页面）结构与样式彻底分离，一处修改全站生效，便于团队协作需要注意文件路径★★★★★ 项目首选
请记住这四句话：① 行内样式只适合临时测试或极少量特殊样式；② 内部样式适合单页练习和课堂演示；③ 外部样式最符合真实项目结构与样式分离的工程要求；④ 本课课件与课堂练习用内部样式是为了方便，但你要清楚——真实项目通常优先使用外部样式表。
工程视角：外部样式表是"代码复用 + 工程规范 + 可维护性"的最小案例。一个团队共享同一份 style.css，风格自然统一——这就是规范带来的效率。

常用选择器：给谁穿衣服

选择器回答的问题是——"这条规则要作用到哪个（些）元素上"。先掌握三种基础选择器（标签、类、ID），再认识复合选择器、伪类和伪元素。

p { }

标签选择器

对应 HTML：所有 <p> 标签

作用范围：页面中所有同名标签，一把全改

段落一被选中

段落二也被选中

常见错误：只想改其中一段，却把全部段落都改了

.card { }

对应 HTML：<div class="card">

作用范围：所有 class 为 card 的元素，可复用

卡片 A 卡片 B

对应 HTML：<h1 id="title">

作用范围：唯一的那一个元素

唯一的大标题

常见错误：漏写 #；同一页面 id 重复

class 与 id 的使用规则

三条铁律：
① 一个 class 可以被多个元素复用，是样式复用的主力；
② 一个 id 在同一页面中应当唯一，像身份证号；
③ 实际开发中，样式优先使用语义清晰的 class。

class 命名的职业习惯

推荐（见名知义）不推荐（含义不清）
.card-title　.course-intro　.start-btn.a　.b1　.red1　.div2

命名是写给同事和三个月后的自己看的——名字表达了用途，代码就自带一半文档。这是严谨，也是责任。

复合选择器（交集）：条件叠加，同时满足

把标签名和类名连写（中间没有空格），表示"两个条件都要满足"才被选中。

我是 p.intro —— 被选中，绿色加粗

我是普通 p —— 没有类条件，不选

我是 div.intro —— 标签条件不符，不选
p.intro

连写 = 且；空格分隔 = 后代（下一个知识点）。两种写法一字之差，含义完全不同。

组合选择器：后代、子代与分组

逗号 = "和"（并集）；空格 = "里面的"（后代）。常见错误：把逗号写成空格，或把后代写成交集。

我是 .box 的直接子代 —— 后代 ✓ 子代 ✓（加粗+左边框）

我是孙代 p（嵌套一层）—— 后代 ✓ 子代 ✗（不加粗）

我也是直接子代 —— 后代 ✓ 子代 ✓

.box p　.box > p

同一个页面里：后代选择器范围更大，子代选择器更精准。日常用后代选择器居多。

伪类选择器：选中元素的"某种状态"

以一个冒号 : 开头，描述元素所处的状态或位置——不是元素本身长什么样，而是"它此刻处于什么情况"。

常用伪类速查：

伪类含义
:hover鼠标悬停（按钮变色的秘密）
:first-child是父元素的第一个孩子
:last-child是父元素的最后一个孩子
:link未访问过的链接
:visited已访问过的链接

现场演示——把鼠标移到下面两处，亲眼看看"状态"被选中：

把鼠标移到我身上 → :hover 生效
  • 第一个 li —— :first-child（红）
  • 中间的 li —— 普通样式
  • 最后一个 li —— :last-child（蓝）
易错点：① 伪类用一个冒号（:hover），写成两个也能用但不规范；② 冒号前后不要加空格（.btn :hover 会变成后代选择器，含义完全不同）；③ :hover 要跟在真实选择器后面（.btn:hover）。

伪元素选择器：选中元素的"某个部分"

以两个冒号 :: 开头，用于选中元素中并不真实存在的部分——比如文字的第一行，或在元素前后"无中生有"地插入内容。

这一段开头和结尾的「」引号，是 ::before 和 ::after 用 content 生成的，HTML 里根本没有这两个字符。

我是 ::first-line 的演示段落：我的第一行会被单独加粗变色。试着拖动浏览器窗口改变宽度——"第一行"的范围会跟着重排，因为它选中的是"位置"，不是固定的文字。后面的文字保持普通样式，用来形成对比。

伪类 vs 伪元素，一句话分清：伪类选中"处于某状态的整个元素"（:hover）；伪元素选中"元素中不存在的某个部分"（::before 插入的内容、::first-line 第一行）。历史原因两者都允许一个冒号，但规范写法是伪类一个冒号、伪元素两个冒号。

第 9 节建议 3 分钟

盒模型：每个元素都是一个盒子

浏览器把每个元素看成一个矩形盒子，从内到外共四层：content → padding → border → margin。它是 CSS 布局的基石，也是排查"间距不对"的地图。

margin（外边距）
border（边框）
padding（内边距）
content（内容）
border：盒子的边界 padding：内部留白 content：内容区 margin：外部距离

四层各自负责什么

  • padding：内容与边框之间的内部空间——把内容从边框里"撑开"一点，别贴着框。
  • margin：元素与其他元素之间的外部距离——负责"我和别人保持多远"。
  • border：盒子的边界，有宽度、占空间。
  • width 默认描述的是 content 区域的宽度，不包含 padding 和 border。
教室类比：课桌桌面是 content；桌面上垫的桌布边距是 padding；桌子本身的边缘是 border；你这张桌子与前后桌之间留的走道是 margin。

可观察盒模型的代码

写完后在 Chrome 开发者工具中选中该元素，Box Model 面板会用同样的四色图显示每层的数值——代码写的和浏览器算的，一一对账。

动手感受：拖动滑块，观察盒子怎么变大

content
宽度固定 240px
盒子在页面上占的总宽度 = 240 + 24×2 + 3×2 + 32×2 = 358 px
拓展提示：box-sizing: border-box（学有余力再看，本课不要求）

加上 box-sizing: border-box; 后，width 将包含 padding 和 border，盒子实际宽度就等于 width 的值。真实项目中常用它简化计算，后续课程会正式讲。现在只需知道"有这个东西"。

盒子模型：margin 40 | border 1 | padding 32 | 320×高度
提示：Styles 面板中的修改是临时的，刷新即还原；确认后请写回代码。
工程视角：调试不是"碰运气"，是取证——先假设、再看证据、再改代码、再验证。主动排查、记录问题、规范修改，是工程师的基本修养。

单选 · 第 1 题

在网页的三层分工中，CSS 主要负责的是（　）

  1. 页面的内容与结构
  2. 页面的样式与表现
  3. 页面的行为与交互
  4. 服务器的数据处理

答案：B

解析：HTML 管内容与结构，CSS 管样式与表现，JavaScript 管行为与交互，各司其职。

单选 · 第 2 题

页面中多个卡片都写了 class="card"，想给它们统一设置样式，正确的 CSS 选择器是（　）

  1. card { }
  2. #card { }
  3. .card { }
  4. *card { }

答案：C

解析：类选择器以点 . 开头；# 是 ID 选择器；不写符号就成了标签名。

判断 · 第 3 题

"同一个页面里，多个元素可以共用一个 class，但一个 id 一般只应出现一次。"（　）

答案：正确

解析：class 是"工种"可以很多人担任，id 是"身份证号"必须唯一。正因如此，样式复用优先用语义清晰的 class。

看效果猜属性 · 第 4 题

卡片与其上方的标题之间空隙明显变大，但卡片内部"文字到边框"的距离没有变化。应该调整的是（　）

页面标题
↑↓ 空隙变大 ↑↓
课程卡片
  1. 卡片的 padding
  2. 卡片的 margin
  3. 卡片的 border
  4. 卡片的 width

答案：B（margin）

代码纠错 · 第 5 题

同学说"我的页面完全没有样式"。请阅读下面两段代码，至少找出两处问题，并说说你的排查思路。

共三处问题：

① link 标签缺少 rel="stylesheet"，样式表没有被当作样式引入；

② CSS 选择器漏了点号，card 应为 .card；

CSS 调试清单：十个高频翻车现场

样式不生效时，不要乱试——按流程走。

六步排查流程

① 保存了吗Ctrl + S
→
② 刷新了吗F5
→
③ 引入对吗link · 路径 · rel
→
④ 选中了吗Styles 有无规则
→
⑤ 被覆盖吗删除线样式
→
⑥ DevTools 看终值最终生效的样式
1. CSS 文件路径错误

典型表现：页面完全没有样式，像是没写过 CSS。

可能原因：href 写的路径与文件实际位置不符（如 CSS 在 css 子文件夹里）。

排查方式：F12 → Network → 刷新，看 style.css 是否 404。

修复示例：<link rel="stylesheet" href="css/style.css"> 与目录结构对应。

2. link 标签缺少 rel="stylesheet"

典型表现：文件明明引了，样式却全不生效。

可能原因：只写了 href，浏览器不知道这是样式表。

排查方式：直接看 link 标签，rel 与 href 缺一不可。

修复示例：<link rel="stylesheet" href="style.css">

3. 类选择器前漏写点号

典型表现：写了规则但页面没变化。

可能原因：card { } 会被当成"叫 card 的标签"（不存在）。

排查方式：F12 选中元素，Styles 面板空空如也 = 没有规则命中。

修复示例：card { } → .card { }

4. ID 选择器前漏写 #

典型表现：同上，规则写了对应元素却不变。

排查方式：对照 HTML 里的写法：id 用 #，class 用 .。

修复示例：title { } → #title { }

5. HTML 的 class 名与 CSS 不一致

典型表现：有的元素生效、有的不生效。

可能原因：大小写不同（.Card ≠ .card）或拼写不同（card-title / card_titel）。

排查方式：F12 里看元素的实际 class，与 CSS 逐字对照。

修复示例：统一命名，复制粘贴而不是手抄名字。

6. 属性名或属性值拼写错误

典型表现：某一条声明不生效，其他正常。

可能原因：backgroud-color、colr 等手误。

排查方式：Styles 面板里该属性不显示，或旁边出现黄色警告图标。

修复示例：不确定拼写时查文档（MDN），别凭感觉。

7. 冒号、分号或大括号遗漏

典型表现：从某一处开始"后面全乱了"。

可能原因：上一行漏分号 / 漏右大括号 / 用了中文标点（：；｛｝）。

排查方式：看"开始失效的那一行"的上一行——错误通常在那里。

修复示例：补上英文半角标点；VS Code 中文输入法下注意切换。

8. margin 与 padding 混淆

典型表现：想拉开两个卡片，结果卡片自己变胖了。

可能原因：把外部距离写成了 padding。

排查方式：F12 的 Box Model 面板看变化发生在哪一层。

修复示例：元素之间的距离 → margin；内容到边框的距离 → padding。

9. 样式被其他规则覆盖

典型表现：明明写了 color，页面却显示另一种颜色。

可能原因：别处还有针对同一元素的规则，且优先级更高或写在后面。

排查方式：Styles 面板里找到带删除线的那条——它输了。

修复示例：合并重复声明，或删掉冲突规则（系统规则下节课讲）。

10. 修改后没保存或没刷新

典型表现："我明明改了！"

排查方式：看 VS Code 标签页有没有圆点（未保存标记）；浏览器是否真的按了 F5。

修复示例：养成"改完就 Ctrl+S，切浏览器先 F5"的肌肉记忆。

工程视角：把每一次踩坑记进自己的"错题本"（问题现象 → 原因 → 修复方法），期末它就是你的《前端排错手册》。主动排查、记录问题、规范修改——这是持续改进的职业方式。

一、为什么值得了解

  • 能力半径："学前端只能写网页"是误解——Web、小程序、鸿蒙应用共用同一套样式与布局思想，换个平台只是换套语法

二、三层迁移：什么不变、什么映射、什么变化

迁移层次规律例子
思想层 · 不变 结构与样式分离、盒模型、属性语义原样成立 padding / border / margin 三兄弟在 ArkUI 中含义完全相同
属性层 · 可映射 命名从连字符改为驼峰，语义一一对应 font-size: 18px → .fontSize(18)
语法层 · 有变化 选择器消失，样式以属性链直接写在组件上 .card { … } → Column() { … }.width(340)
